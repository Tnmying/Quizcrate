# 阶段 01：环境与 PDF 提取可行性

任务状态：待 DSH 开始。完成后停止，等待 Codex 验收。不开发完整 UI，不自动进入阶段 02。

## 目的

证明存在可在安卓手机完全离线运行、能处理真实样本关键排版的解析路线。先解决文字和下划线定位，不先搭建完整应用。

## 步骤

1. 阅读根目录 AGENTS.md 和 docs/PROJECT_BRIEF.md，确认工作目录。以只读方式检查 Java/JDK、Node、Python、Gradle、Android SDK/构建工具等现有环境，记录真实可执行路径和版本；不读取凭据或会话历史。
2. 检查 local-inputs/sample.pdf：文字层、页数、文字顺序、字符坐标及下划线绘图信息。提取完整文本到 work/ 便于独立检查。
3. 查阅候选解析库的官方文档/源码，选择可在 Android 离线运行的路线，说明许可证、可维护性、文字/字符位置和绘图线段能力。优先现成库，不承诺尚未验证的 Android 支持。可以先用 Python 辅助观察，但这不能替代 Android/JVM 路线验证。
4. 尽可能实现小型可重跑提取验证，生成统一题目 JSON（含题型、原编号、题干、选项、答案列表、来源页码、待校对标记），解析样本各类题。代码中不能硬编码样本的题干、答案、题量，不能通过调用 AI 提取或补全。
5. 特别展示填空题的“原句 → 挖空题干 → 各空答案”，证明依据真实下划线或可解释的排版证据定位。处理同一答案跨行的情况；不确定时标记人工校对。不能凭常识猜答案位置。
6. 对照检查编号跳号、页末孤立 6.、页脚去除、多选多答案、跨行选项和参考答案拆分。验证每个题型的实际数量并解释与基线的差异，保留原编号，禁止捏造缺失 92 题。
7. 写交接报告并停止。

## 输出

- `docs/reports/01-dsh-report.md`：环境、选择的路线/库及来源、实际执行命令、提取数量、关键案例、失败与限制、下一步最小建议。
- `work/phase-01/`：原始提取结果、统一题目 JSON、必要渲染图和临时产物。
- 可复现的验证程序，位置自行合理安排（如 `tools/pdf-probe/`）；在报告中给出不含秘密的准确运行方式。工具依赖必须说明版本。
- `docs/STATUS.md`：标注 `PHASE_01_READY_FOR_REVIEW` 或 `PHASE_01_BLOCKED`，列出简短结果/阻碍，不得自行标为已验收。

## 范围和停止条件

可以在项目内安装必要的小型解析验证依赖，但不全局安装，不下载 Android Studio/完整 SDK，不修改环境变量或系统设置。如缺少 JDK/SDK 阻碍真实 Android/JVM 验证，先完成可独立推进的分析，准确标记尚未验证，并报告需要的最小环境。
出现同一依赖错误两次应换方法或报告，不要无止境重试。完成或遇到阻碍时，在 DSH 回复中简要指出报告位置并停止。

## Codex 独立验收点

- 文件真实存在；验证程序可重跑，结果不是抄写或硬编码样本。
- 文字与下划线分离正确，跨行空和编号异常不会产生假题。
- 解析路线可用于安卓离线；仅桌面原型不能宣称通过手机可行性验收。
- 数量与各类型代表题对照原文；不确定内容保留可校对标记。
- 没有提前搭完整应用、安装协作框架、发布或修改项目外设置。
