# 阶段 02A 小改：跨行合并与顿号拆空

日期：2026-11-03。用户明确确认本任务规则，Codex 已授权 DSH 执行。完成后停止，用户会手动通知 Codex 复查；不进入 02B，不持续监控，不实现完整刷题。

## 用户确认的规则与顺序

1. 同一行，依据原文独立下划线范围确定原始答案区域。保留来源页码、位置和原文证据，不能用语义猜测挖空。
2. 跨行时，检查前一段是否延续到行尾、后一段是否从下一行开头继续。只有位置/文本关系明确时才合并为一个原始答案区域。
3. 两段之间存在未划线标点或其他正文时，不合并。检查真实文字索引间隙，不能只凭坐标靠近就吞掉未划线正文。下划线覆盖范围内部的标点原样保留在原始答案区域。
4. 条件明确则自动处理。cross_line_underline 只是发生跨行处理的事实，不能无条件等同 needsReview=true。发生歧义、覆盖边界不确定、文字缺失/重叠等情况仍需标记待校对，不能简单删除全部警告。界面用清楚中文解释，不向用户显示内部英文 reason code。
5. 完成上述原始区域识别/跨行合并后，**仅按该已识别填空答案内部的中文顿号 `、` 拆成学习用子空**。不按逗号（中英文）、分号、句号、冒号或其他标点拆空。
6. 例如同一个下划线答案区域是 `有理想、敢担当、能吃苦、肯奋斗`，练习/预览题干变为 `____、____、____、____`，四个答案按原顺序为 `有理想`、`敢担当`、`能吃苦`、`肯奋斗`。原文证据与子空关系保留，标点留在题干；下划线位置信息不能冒充新增四条物理下划线。
7. 只对 fill_blank 题型的已识别答案区域执行；不要对整道题/未划线正文拆分，也不把真实题库中的简答第 2 题自动转换成填空。简答参考答案保持原样。
8. 连续或首尾顿号不生成空答案；保留原文并标为歧义待校对，防止静默丢失。拆分操作可重复执行而结果不重复变化；多个独立原始空不能因标点规则串成一个空。

## 实现与边界

- 先读 AGENTS.md、docs/PROJECT_BRIEF.md、既有阶段 01/02A 报告。当前用户已在 RMX3800/Android 16 上安装并看到预览和校对标记；尚未拿到完整真机计数，不把截图等同所有指标已通过。
- 规则集中在共享纯逻辑，Android 与桌面探针保持一致；原始字形/下划线几何证据和展示/学习子空分离，选择最小清楚的数据结构，不必过度设计。
- 若下划线末尾标点已在提取时修剪，跨行判断仍要检查原文中的未覆盖间隙；不要把被修剪的分隔符当成不存在。
- 明确不合并的相邻两段，是两个原始区域；不能通过后续顿号拆分来掩盖错误合并或吞正文。
- UI 将 needsReview 原因映射为中文；正常明确跨行不红色报警，歧义仍解释具体原因。合并事件可以保留为非警告诊断信息。
- 不重做其他界面，不添加登录/联网/AI，不改变题型，不加协作插件。不安装新 Android 环境，复用已有项目内工具。

## 必要测试与验收

增加可重复运行的有意义回归，至少覆盖：

- 一个原始空含四个顿号分隔项，输出四空，答案顺序与标点正确。
- 相同答案跨行后先正确合并，再拆成四空；不同排版换行不能改变最终空数量。
- 两段下划线之间存在未划线的 `、` / `，` / `和`，不吞文字、不误合并。
- 下划线内部有逗号/分号，仍是一个学习空；只有 `、` 触发拆分。
- 未划线正文中的顿号不产生新空，简答原题保持原样。
- 独立多个空、连续/首尾顿号、歧义边界：没有空答案，必要待校对原因准确。
- 无歧义的跨行答案不再仅因跨行就标 needsReview；真正有歧义仍标记。
