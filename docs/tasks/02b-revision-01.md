## R1：合并空保持题意且不接受半个答案

- 复现见 `work/codex-review-02b/ReviewBlankMerge.java`，它直接调用本次实际 Kotlin 编译产物。不要把当前错误测试的预期当作需求。
- 在结构匹配的题干中，合并相邻两个空须把**两个占位符和中间分隔内容整体替换为一个占位符**，并用原中间内容连接两份参考答案。因此 `前____、____后` + `[甲,乙]` → `前____后` + `[甲、乙]`；不得留下第二份顿号。
- 中间有普通正文时采用保守方案：**拒绝自动合并并给中文提示**，保持题干、答案、可接受答案全部不变，用户可手动校对。至少 `____和____`、`____后又____` 不得被改成 `甲、乙`。可自动处理的空白/标点白名单要明确且测试；不许无条件用顿号连接。纯空白间隔也要保留明确的文本含义，不能凭空补顿号。
- 合并后的可接受答案不能是两个旧集合的并集。第一版采用简单保守方案：**清空该合并空的额外可接受答案并提示用户重新设置**，保留正确的合并参考答案，其他空的可接受答案保持原顺序；无需组合穷举算法。
- 操作前若题干占位符数与答案数不一致，拒绝合并并提示先校对，避免根据错位索引改错空。不能静默忽略失败。
- 这些是用户手动校对时的合并操作；不修改已验收的 PDF 自动识别/仅顿号拆空规则。

## R2：保存期间不丢输入

- 保存进行中禁用正文、选项、答案、空位增删合并等全部修改控件，并在 ViewModel 统一 mutate 入口防护；保留保存失败后的原编辑内容与错误反馈。不要只禁用底部保存按钮。
- 用可控延迟/挂起仓库验证：保存 A 未结束时尝试改 B，不得出现 UI 接受 B 后又被回读 A 静默覆盖。可按当前架构加入最小可测状态边界；不为测试重搭整个项目。
