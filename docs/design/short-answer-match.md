# 简答文字匹配辅助设计与评估（03C）

日期：2026-11-03。算法版本：`dice-char23-v2`（v2 修正数值标点与预处理边界）。实现：`android/app/src/main/java/com/offlinequiz/app/model/ShortAnswerTextMatch.kt`。

本文的评估样例全部自制，不使用真实题库正文。

## 定位与边界

- 完全离线、纯 Kotlin，无网络、AI、词典或大型依赖。
- **只展示文字重合度**，不是答案正确率，不设及格线/判对阈值，不替用户选择“记得/没记住”，不进入自动正确率、错题资格或掌握状态。
- 只有展开参考答案后才显示；未展开不显示，避免泄露答案。
- 计算基于当前练习的**固定题目快照** `referenceAnswer` 与当时输入；改题库不会改变旧会话的比较基准。自评提交后的反馈用同一条记录的用户答案重算，同一题显示同一分数。

## 规范化（保守）

对两侧文本分别执行，原输入不被修改：

1. 按 Unicode **码点**遍历，绝不拆开代理对（emoji/CJK 扩展区安全）。
2. 全角 ASCII（U+FF01–U+FF5E）折叠为 ASCII；表意空格 U+3000 折叠为普通空格。
3. `Locale.ROOT` 小写。
4. 删除空白（`Character.isWhitespace` 或 `isSpaceChar`）。
5. 删除**明确列出的普通排版标点**：
   - ASCII：`,` `.` `!` `?` `;` `:` `"` `'` `` ` ``
   - 中文：`、` `，` `。` `！` `？` `；` `：` `…` `—` `–` `·` `•` `“` `”` `‘` `’` `「` `」` `『` `』` `《` `》` `【` `】` `〈` `〉`
   - **例外（v2）**：`.` `:` `,` 如果**紧邻两侧都是数字**（同一规范化前缀内、无空格），则保留为数值分隔符。因此：
     - `1.5` ≠ `15`，`0.5` ≠ `05`，`1:2` ≠ `12`，`1,000` ≠ `1000`
     - 全角 `1．5`/`1：2`/`1，000` 先折叠为 ASCII，与半角等价
     - 句末 `1.`、标签后的 `：`（如“答案：1.5”）仍作为普通标点删除
     - 数字之间的逗号也保留（宁可保守保留，不臆测是列表还是千分位）
6. **保留**其余所有字符：字母、数字、否定词（不/无/未/非/否…）、条件词（至少/至多/低于/高于/如果…）以及数学/比较符号（`+` `-` `%` `<` `>` `=` `/` `*` `(` `)` `[` `]` `{` `}` 等）。
7. **不删除**“的/了”等停用字，**不引入**分词词库，避免把复合词或否定拆坏。

## 相似度

对阶数 n ∈ {2, 3}：

- 用滑动窗口取所有长度为 n 的码点 gram，按出现次数构成**多重集**；重复内容会同时出现在分母，堆字不能刷满分。
- 重合数 = 对每个 gram 取 `min(countA, countB)` 后求和。
- `Dice_n = 2 × 重合数 / (A 的 n-gram 总数 + B 的 n-gram 总数)`。
- 一侧长度不足 n、另一侧足够时，该阶为 **0 分并参与平均**，不是跳过。
- 仅当两侧都没有该阶 gram（都很短）时才跳过该阶。
- 最终分数 = 可用阶的**等权平均**；显示为 0–100% 的整数（四舍五入）。

回退与上限：

- 双方规范化后都只有 1 个码点：使用明确的**单码点比较**（相同 100%，不同 0%），并提示“文本过短，单字比较参考有限”。
- **v2 预处理边界**：每侧最多扫描 **8000 个原始码点**做折叠/小写，最多保留 **2000 个有效码点**参与比较。因此预处理输出、内存与主线程工作量都有明确上限，不只是限制 gram 计数。
- 一旦超出任一上限，`truncated=true`，界面明确提示“文本较长，仅比较开头部分（最多 2000 个有效字符）”，不静默截断，不阻止自评/保存/跳过。
- 无设备时同步计算即可（上限为 8000 码点，量级很小），因此不存在异步迟到结果覆盖后续题目的竞态。
- 空输入、参考答案为空、规范化后为空：给出对应中文空态，不把两个空答案算 100%，也不把“心中作答”显示 0 分。
- 全程无除零/NaN；线性遍历，内存有界。

## 手算校验例

参考“甲乙丙”，输入“甲乙”：

- 2-gram：参考 {甲乙, 乙丙}，输入 {甲乙}，重合 1 → `2×1/(2+1)=2/3≈0.6667`。
- 3-gram：参考 {甲乙丙}，输入无 → `0`（参与平均）。
- 最终 `(0.6667+0)/2≈0.3333` → **33%**。

该数值由 `ShortAnswerTextMatchTest` 断言。

## 局限（必须如实呈现）

- **不理解语义**：同义改写因用词不同只得 29%；不能因为分数低就判定用户答错。
- **否定词只算字符**：参考“需要光照”与输入“不需要光照”得 83%，虽然意思相反。`ShortAnswerMatchEvaluationTest` 将该高分作为已知局限固定下来，提示用户自行判断。
- **数字/条件变化可能高分**：10→30 摄氏度得 80%，至少→至多得 70%；同样不是语义判断。
- **语序变化**：甲/乙互换得 45%，属于中等重合，不能证明逻辑关系。
- **堆字**：重复参考两遍得 55%，分母计入重复内容所以不能满分；但继续堆相关字仍可能推高分数，不能当作“掌握”。
- **短文本**：双方都只有 1 个字时只能做单字相同/不同比较；一侧过短时对应阶为 0 分，分数可能偏低。
- **标点/空白/全半角/大小写**被规范化；不同标点习惯可能带来分数差异，但这只影响文字重合。
- **数值标点只做保守保留**：数字之间的 `.`/`:`/`,` 保留，因此 `1.5` 与 `15`、`1:2` 与 `12` 不再等同；但不解析数学含义，`1.50` 与 `1.5` 字符不同仍会不同分，`1.5` 与 `1,5` 也因分隔符不同而不同。
- **空格千分位**：`1 000` 中的空格仍按空白删除，会与 `1000` 相同；这是已知边界，未臆测空格含义。
- **长度上限**：预处理最多读取 8000 个原始码点、保留 2000 个有效码点；**超出前缀之后的差异不会被看到**（测试固定了这一边界），界面会提示仅比较开头部分。
- 该指标**不能**作为自动判对、及格线、错题本资格或掌握状态；界面文案固定包含“仅比较文字重合，不代表答案正确；请自行判断”。

## UI 行为摘要

- 仅简答题；展开参考答案后，有输入时显示“文字匹配度 N%”，无输入显示“尚未输入文字…”。
- 参考答案缺失/为空/规范化后为空显示对应中文空态。
- 自评提交后的反馈（自评记得/没记住）显示同一比较结果；跳过不显示。
- 切题/恢复/改题不会复用旧分数；恢复草稿且已展开时按快照重算。
- 计算在 ViewModel 中随状态变化执行（展开、输入、状态恢复、反馈），不在 Compose 每次重绘时计算；v2 起预处理和比较都有上限，主线程同步计算即可，不存在迟到结果覆盖后续题目的竞态。
- **展开后输入框保持锁定**（既有行为，本阶段未改）：要看另一段文字，请在同一题展开前输入，或进入下一题/新一轮再输入。
